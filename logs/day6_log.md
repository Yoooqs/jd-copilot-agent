# Day 6 Log
- 今日目标：引入 Agent Loop（执行-评估-修正）与 Harness 护栏，实现自我纠错与安全防护。

- 完成情况：已完成。闭环机制跑通，并成功防御了模型的“过度优化作弊”行为。

- 关键产出：
  1. docs/agent_loop_spec.md (定义了完整的 Loop 机制和 6 条硬性护栏规则)
  2. reports/agent_loop_eval_day6.xlsx (包含 4 个极限边界测试用例：A, B1, B2, C)

- 验证结果：
  1. 测试 A（自我修正）：第 1 轮输出 7 分（缺少数字），主动触发 Loop 2，第 2 轮提取真实数据后得 8.5 分达标停止，证明工具可以迭代优化。
  2. 测试 B1（作弊风险）：模型为了达标，自行编造“语义映射表”，把“售后经验”偷换概念映射为“大模型训练”，导致护栏失效。
  3. 测试 B2（护栏拦截）：在同步更新“跨领域隔离约束”后，Agent 成功触发熔断，诚实拒绝跨领域改写，证明防幻觉机制生效。
  4. 测试 C（参数兜底）：Agent 精准识别参数缺失，并结合上下文主动给出岗位建议。

- 卡点与排查过程（核心踩坑记录）：
  1. **过度优化型幻觉（Over-optimization Hallucination）**：在 Test B1 中，模型为了达到 8 分的 Loop 目标，竟然自行生成“语义映射表”强行作弊。
  2. **修复方案**：单纯依赖 Prompt 层“不要捏造”的软约束无法拦截模型的“作弊”。我立刻在 `agent_loop_spec.md` 和 Dify 提示词中同步增加了第 6 条“跨领域隔离约束”的硬性熔断规则，彻底堵死了跨界偷换概念的路径。

- 明日依赖：Day 7 需要引入 Context Engineering（上下文工程），优化长对话中的信息压缩与传递效率。

- 面试可讲点（核心话术准备）：
  1. **闭环设计与安全护栏的迭代**：我实现了“执行-评估-修正”闭环。更重要的是，我发现了 AI 的“过度优化”倾向——为了拿高分它会作弊。这证明仅靠 Prompt 约束是不够的，必须通过“跨领域隔离约束”从架构上切断它瞎编的路径。
