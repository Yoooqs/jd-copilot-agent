- 验证结果（实测数据）：
  1. 测试 A（正常执行）：业务分析精准。但模型对物理指标估算严重偏低（估算12秒/6000 Token，实际154.74秒/17453 Token）。
  2. 测试 B（护栏拦截）：成功拒绝跨领域改写请求，状态和错误类型准确。模型同样低估耗时（估算5秒/3600 Token，实际31.42秒/11000+ Token）。
  3. 测试 C（参数缺失）：拒绝盲目生成计划，列出5个真实岗位引导用户澄清。**但发现任务未完成时，模型遗忘了 JSON 日志输出指令。**

- 卡点与排查过程（核心实战踩坑记录）：
  1. **物理指标盲区**：模型无法感知系统真实的延迟和 Token 消耗，估算误差高达 10 倍。证明了“双轨制日志”的必要性：语义日志（工具调用、拦截状态）由模型生成，物理日志（延迟、Token成本）必须由平台底层采集。
  2. **日志指令遗漏**：在 Test C 中，因任务未完成（等待用户输入），模型选择不输出日志。这也印证了模型指令遵循的局限性，系统可观测性必须依赖硬编码而非自然语言约束。
