# JD Copilot 可观测性（Observability）与监控策略

## 一、 核心监控指标（Golden Signals）
为了保障 AI 产品稳定运行，必须追踪以下核心指标：

1. **性能指标（Performance）**：
   - 端到端延迟（P95 < 30秒）
   - 首字响应时间（TTFT）
2. **成本指标（Cost）**：
   - 单次会话的平均 Token 消耗（目标 < 10,000 Tokens）
   - 单次会话的平均 API 成本
3. **质量指标（Quality）**：
   - 工具调用成功率（Tool Call Success Rate）
   - 护栏拦截率（Harness Interception Rate，如跨领域拒绝次数）
   - Agent Loop 平均循环次数（目标 < 2次）
4. **错误指标（Errors）**：
   - API 超时率 / 报错率（如 Dify 额度耗尽、网络抖动）

## 二、 结构化日志标准（双轨制日志）

**核心洞察（基于 Day 8 测试）**：大模型无法准确感知系统级的物理指标。因此，AI 产品的可观测性必须采用“双轨制”，绝不能让模型估算物理数据。
*本设计V2.0 生产级方案，Day 8 在 Dify MVP 阶段通过单轨制 Prompt 模拟了语义日志，并在 Test A 中验证了模型估算物理指标的严重误差。*

### 1. 语义日志（由 Agent 生成）
- `timestamp`（时间戳）
- `session_id`（会话ID）
- `user_query`（用户提问）
- `tool_called`（调用的工具名称）
- `loop_count`（循环次数）
- `status`（成功 / 失败 / 被护栏拦截）
- `error_type`（如果是失败，具体的错误分类）
*（注：用于业务逻辑分析、护栏监控与用户体验排障）*

### 2. 性能与成本日志（由平台/网关底层自动采集）
- `latency_ms`（真实的端到端耗时，如 154742ms）
- `prompt_tokens`（真实的输入消耗）
- `completion_tokens`（真实的输出消耗）
- `total_tokens`（真实的整体消耗，如 17453）
*（注：用于成本核算、系统性能告警及 API 额度管理。绝不能由大模型估算！）*

## 三、 异常监控与告警机制（Alerting）
- **一级告警（P0）**：API 额度耗尽、大模型接口全面瘫痪、跨领域护栏频繁被突破。
- **二级告警（P1）**：单次消耗 Token 超过 20,000、平均延迟超过 60 秒。
- **降级预案**：当 API 额度耗尽时，自动切换至备用 API Key（如从 Dify 内置切换至硅基流动），并弹出“系统维护中”提示，而不是直接崩溃。
